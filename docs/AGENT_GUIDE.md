# Инструкции агенту

## Контекст и порядок чтения

Работаем в формате «один владелец + один ИИ». Реализована локальная версия 0.1.0. Текущий статус и оставшиеся проверки — в TASKS.md; не путать реализацию с ручной приёмкой владельца.

В начале работы прочитай [README](../README.md), текущий статус и выбранную задачу в [TASKS.md](../TASKS.md), затем соответствующие разделы [PRODUCT.md](PRODUCT.md) и [ARCHITECTURE.md](ARCHITECTURE.md). [PROVIDERS.md](PROVIDERS.md) нужен для сетевой интеграции, [TESTING.md](TESTING.md) — для проверки. Не перечитывай весь комплект после каждого небольшого изменения.

## Обязательные договорённости

- V1: только EN → RU, Ctrl и фиксированные 500 мс; без настроек и дополнительных режимов.
- Пользовательский popup — элемент поверх страницы, не окно панели инструментов Chrome.
- Выбран MyMemory без ключа и биллинга; примеры — Free Dictionary API. Не выдавать мок или единичный HTTP-ответ за готовую браузерную интеграцию.
- Перевод обязателен. Примеры и произношение реализованы при наличии данных/голоса; недоступность обрабатываем явно, без выдуманных данных.
- Сохраняй приватность: только слово, никакого текста страницы, URL или истории просмотра в прикладном запросе.
- Не подключай платные услуги, backend, аналитику, публикацию или remote без отдельного запроса. Не обходи CAPTCHA, ограничения или TLS-проверки.

## Внесение изменений

Веди задачи и короткие результаты в `TASKS.md`. Архитектурные решения записывай в `ARCHITECTURE.md`, требования — в `PRODUCT.md`; не создавай параллельные списки статуса. Для обычной задачи достаточно результата, целевых проверок и локального коммита по [WORKFLOW.md](WORKFLOW.md).

Используем JavaScript ES modules, Manifest V3, esbuild и встроенный `node:test`. Команды: `npm ci`, `npm test`, `npm run build`, `npm run dev:fixture`. `npm run check:providers` делает живые запросы и не входит в обычные тесты. Новые команды документируй после их появления и запуска.

Код: отступ 2 пробела, `const` по умолчанию, `camelCase` для функций и переменных, `UPPER_SNAKE_CASE` для констант, `kebab-case.js` для файлов, `*.test.js` для тестов. Изменения поведения сопровождай полезными проверками; для правок документации достаточно ссылок и diff.

Перед изменением проверь чужие незакоммиченные правки. Не стирай их и не применяй разрушительные Git-команды. Не запускай обязательные роли, делегации, таск-трекеры, PR или многоступенчатые согласования. Если данных недостаточно, продолжай независимую работу и обозначь конкретную нерешённую зависимость.
